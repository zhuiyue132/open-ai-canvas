# Agent Note: 品牌首页走独立公开入口，场景用既有 Three.js 而不引新依赖

Status: implemented

## Problem

公开首页要同时讲一个故事并把访客送进工作台。工作台路由 `/`、`/create`、`/home` 都先恢复登录态、再加载模型目录，把品牌叙事放进同一个应用外壳，首屏必须等这两件事完成，公开页与业务入口互相拖慢。首页还大量使用 Blender 开放电影素材，署名与许可必须落在访客可达的位置，否则视觉资产的分发缺少依据。

## Decision

`/welcome` 是公开入口，由 `web/src/welcome-application.tsx` 独立挂载，`web/src/main.tsx` 精确匹配该路径并保留启动 URL 清理；账户认证与业务权限仍由工作台负责，首页用普通链接进入工作台。首屏在纹理与视频加载前就显示标题与 CTA，文字是真实 DOM。

场景由 `web/src/pages/welcome/story-reel.tsx` 用仓库既有的 Three.js 实现：影像卷轴、阶段材质、轨迹与节点展开；文案与素材清单在 `web/src/pages/welcome/story.ts`；视觉 token 与响应式只在 `web/src/pages/welcome/welcome.css` 生效，不污染全局样式。不引入 OGL 或 GSAP，也不复制参考实现的图片、字体、全局 CSS 与广告脚本。

素材分 Spring（默认）、Charge、Wing It! 三版本，用 `?look=` 直接打开；切换保留滚动位置并支持浏览器前进、后退。素材位于 `web/public/welcome/`，CC BY 4.0 的作者、来源、裁剪说明在 `/welcome/credits.html`，该第三方许可不被应用代码的 MIT 覆盖；页内不把第三方镜头宣称为影策生成案例。

降级路径固定：减少动态效果偏好、图片加载失败或 WebGL 创建失败时退到静态画面；手机端缩短滚动距离并调整摄影机行程；首屏影像背景随滚动渐隐为黑底，返回顶部恢复。

## Alternatives considered

- **复用工作台路由，在同一应用外壳内做首页** — 能直接复用导航、主题与认证态，改动面最小。否决条件是不成立的：它让公开页继承登录恢复与模型目录请求的等待，且"无后端 API 请求"这条验收入口无法成立。
- **照参考 Demo 用 OGL + GSAP 复刻镜头运动** — 参考实现已完成调参与美术验证，视觉上限有现成答案。否决理由是依赖代价：为一个页面引入两套渲染/动画栈，而仓库已有 Three.js 与原生滚动进度可达到同样的镜头语言。
- **背景在 WebGL 加载后立即消失** — 实现更简单，状态机只跟加载事件走。否决理由是资源加载期间会出现空场，改为与滚动进度绑定，返回顶部时恢复。
- **三个素材版本合并成一套循环编排** — 素材维护减少三分之二。否决理由是素材许可与分辨率差异太大，Charge 有静音预告片段、Wing It! 是低分辨率彩稿，混用会破坏署名与"适合方向预览"的说明。

## Consequences

- **收益**：公开页与服务端解耦，可独立验收"不访问后端"；品牌叙事与工作台各自演进；素材许可与署名同页可达；主题与响应式改动局限在 `welcome.css`。
- **代价与已知上限**：单页承载 Three.js 场景与十二个卷轴位置，首屏依赖 WebGL 与纹理加载，低端设备与移动端需靠降级路径兜底；Wing It! 部分彩稿分辨率偏低，只适合方向预览。已知未确认项是 iOS Safari 真机（地址栏变化、长时间浏览帧率与设备发热）。

## Verification

- 语义与素材契约：`cd web && bun test test/welcome-story.test.ts` — 3 passed / 0 failed（含"署名分别覆盖三套素材，独立于代码许可"）。
- 浏览器与构建证据（上游基线的独立分支记录）：完整前端构建、素材与启动清理专项测试、生产预览下 1440px 与 390px 的三版本切换、六幕滚动、非空画布与动画、Charge 视频、历史返回、减少动态效果与署名页检查。
- 素材与许可入口：`web/public/welcome/credits.html`。
- 详细分幕文案、素材编排与视觉约束见上游遗产 `docs/design/story-creation-homepage.md`（只读）。
